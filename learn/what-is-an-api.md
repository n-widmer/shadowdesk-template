# What an API is

## In one line

An API is a doorway a program leaves open so another program can ask it for things, with no human clicking around.

## The picture

Think of the drive-through window at a restaurant. It is a small opening, not the front door. You can ask for what is on the menu, and you get it fast. The limit: you can only order what the menu lists. A tool only offers what it chose to offer, so sometimes the answer is that it has no door for that.

## Why you care

This is how work gets done while you are not watching. Prep for a call from your calendar. A follow up to a client who went quiet. Reminders for the invoices nobody paid. Without a doorway, someone sits and clicks.

## What this looks like in your setup

`CONNECTIONS.md` is the list of doors that are open for you. Section 2 names six worth opening first, like Gmail and Google Calendar. An API key is the badge that proves who is knocking, so a key is a password. Section 3 records only the name of each key, never the key itself. `references/api-keys.md` has the handling steps. You never store or manage a key yourself. I follow that written protocol.

## Try this

Pick one tool you already pay for. Say: "What would an API unlock for [tool]?" You should see a short list of real jobs, and an honest note where that tool has no door.
